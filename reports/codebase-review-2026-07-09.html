Swagger uses a public PKCE client without a secret

Implemented

What changed

  • clientSecret was removed from Swagger initialization and from API runtime settings.
  • OIDC_DOCS_CLIENT_ID=fastapi-docs selects a public client.
  • Both Keycloak realm exports define that client with standard flow enabled, direct grants disabled, and S256 PKCE required.
  • An audience mapper adds fastapi-client to the access token so the existing API validator accepts the login token.

Why login still works

The browser sends the authorization code plus its PKCE verifier to the token endpoint; no client secret is expected from a public client. The existing confidential fastapi-client remains available for scenario-test token acquisition.

04

Entity pagination has one safe, user-selected ordering

Implemented

The route uses enums rather than passing arbitrary column text into SQL. Every entity-table column except id is represented, and invalid values return the existing 400 validation problem.

Important constraint: ordering by a non-unique column cannot mathematically guarantee stable boundaries when values tie or rows change between requests. The requested one-column/no-ID contract is implemented; a unique tie-breaker or cursor would be needed for strict determinism.

API contract
GET /entities/?
  offset=0&limit=25&
  order_by=name&
  order_direction=desc

order_by ∈ {
  name, description,
  created_at, updated_at
}

Exactly one column; id is rejected.

Design decisions and researched recommendations

A

OIDC discovery belongs at application startup — inside lifespan

Recommended next refactor

Your startup instinct is correct. The problem is not “fetch at startup”; it is that the current fetch happens synchronously while Python imports app/settings/authentication.py. Import-time I/O also runs for unit-test collection, CLI inspection, migration tooling, and anything else that imports settings.

Best solution

  • Keep AuthNSettings limited to raw environment input: issuer URL, client IDs, cache TTL, and optional complete endpoint overrides.
  • Create an immutable OIDCMetadata model for issuer, jwks_uri, authorization_endpoint, and token_endpoint.
  • Before yield in FastAPI lifespan, call an async discover_oidc_metadata() using one httpx.AsyncClient, explicit connect/read timeouts, and a small bounded retry.
  • Validate that the discovered issuer exactly matches the configured public issuer. The OpenID specification requires this equality.
  • Store the resolved metadata in lifespan/application state or a small dependency container; construct the OAuth scheme and JWKS client lazily from that resolved object.
  • Fail startup clearly after bounded retries. The process must not become ready with incomplete trust configuration.
  • If all four endpoint overrides are supplied, validate them as a complete group and skip network discovery. Reject partial groups.

Sources: FastAPI lifespan events; OpenID Connect Discovery 1.0.

Recommended lifecycle
1. Python imports modules
   no network I/O

2. FastAPI lifespan starts
   configure logging
   await discover_oidc_metadata()
   validate issuer + required fields
   create auth runtime / JWKS client

3. Mark application ready
   yield

4. Serve requests

Failure policy:
bounded retry → explicit startup failure
never partially configured auth
B

SHA pinning does not stop Renovate or Dependabot updates

Research answer

Yes, both bots can update full-SHA GitHub Action references. Pinning changes the workflow runtime from “whatever this mutable tag points to today” to “the exact reviewed commit.” The bot then opens a PR that changes the SHA when a newer tagged release exists.

Renovate

Renovate documents digest pinning and updating directly. Use a full SHA plus an adjacent version comment, and add helpers:pinGitHubActionDigests if you want Renovate to convert tags automatically. A bare SHA without a tag/version comment is disabled by default because Renovate cannot determine which release line it belongs to.

Dependabot

GitHub documents support for both owner/action@vN and owner/action@<commit>. It also updates same-line version comments. If a SHA is not associated with a tag, Dependabot may move it to the latest commit rather than the latest release, so a tagged SHA and readable comment are preferable.

Sources: GitHub secure use reference; Dependabot GitHub Actions support; Renovate GitHub Actions manager.

Recommended syntax
# Immutable runtime + readable release
uses: actions/checkout@<40-char-sha> # v7.0.0

Renovate option:
{
  "extends": [
    "config:recommended",
    "helpers:pinGitHubActionDigests"
  ]
}

Result:
bot PR updates SHA and version comment;
CI never follows a moved tag silently.

Reclassified · not a defect

D

Concrete template identity and parallel-Compose solution

Proposed for review

What “template identity” means

name = "fastapi-template" is a reasonable default identity. The unfinished part is only the placeholder package description. Replace it with a truthful description and add an adopter checklist for service name, package metadata, image names, OIDC clients, and observability project IDs.

What “Compose portability” means

Fixed container_name values occupy host-global names such as postgres. A second checkout, worktree, CI shard, or developer stack cannot create another container with that name. Compose already gives stable internal DNS using service names (db, keycloak, app), so explicit container names are unnecessary.

Final recommendation

  • Remove all four container_name lines.
  • Parameterize host ports so parallel stacks do not collide.
  • Run each stack with a distinct project name: docker compose -p feature-a up.
  • Keep service-to-service URLs unchanged: db:5432 and keycloak:8080.
  • Document the default description and the adopter rename checklist.

For a parallel stack that also uses Swagger login, register that stack’s exact callback (for example http://localhost:8081/docs/oauth2-redirect) in its IdP client. Do not solve this with an unrestricted production redirect wildcard.

Proposed final shape
# pyproject.toml
description = "Production-minded FastAPI service template with OIDC, PostgreSQL, Alembic, telemetry, and layered tests"

# docker-compose.yml
# delete every container_name

    - "${KEYCLOAK_PORT:-8080}:8080"

    KC_HOSTNAME_URL: "${OIDC_PUBLIC_URL:-http://localhost:8080}"
